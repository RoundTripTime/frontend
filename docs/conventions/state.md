# 상태 분류 규칙

## 목적

앱 상태는 서버 / 클라 / URL / 폼 4가지로 분류한다.

## 분류 기준

| 분류 | 기준 | 사용 기술 |
| --- | --- | --- |
| 서버 상태 | 백엔드, 외부 API, DB, 캐시, 스토리지에서 조회하거나 변경되는 데이터 | TanStack Query |
| 클라 상태 | 화면 간 유지가 필요하지만 서버 저장 대상이 아닌 앱 내부 상태 | Zustand |
| URL 상태 | 화면 진입 경로, Deep Link, 공유 링크, 탭/상세 화면 식별에 필요한 라우팅 상태 | Expo Router |
| 폼 상태 | 제출 전 입력값, 선택값, 검증 오류, 임시 편집값 | 화면 로컬 상태 |

## 적용 규칙

### 서버 상태

- 저장한 장소, 장소 후보, 장소 상세, 플레이스, 플랜, 포스트, 댓글, 프로필, 팔로우, 크레딧, 광고 시청 결과처럼 서버와 동기화되는 데이터는 서버 상태로 둔다.
- 링크 분석 잡, 분석 완료/실패, 푸시 알림의 읽음 처리처럼 백엔드 처리 결과를 반영하는 값은 서버 상태로 둔다.
- 캐싱, 재조회, 낙관적 업데이트가 필요한 값은 TanStack Query로 관리한다.

### 클라 상태

- 로그인 여부에 따른 초기 분기 이후의 앱 내부 UI 상태, 현재 선택된 탭, 일시적인 토스트 표시 여부처럼 서버 저장 대상이 아닌 값은 클라 상태로 둔다.
- 여러 화면에서 공유해야 하는 앱 내부 상태는 Zustand로 관리한다.

### URL 상태

- 하단 탭, 상세 화면 식별자, 공개 플랜/플레이스 공유 링크, 외부 공유 링크 진입, Deep Link로 복원되어야 하는 값은 URL 상태로 둔다.
- 뒤로가기, 새로 진입, 공유 링크 진입 시 동일 화면을 재현해야 하는 값은 URL 상태로 둔다.

### 폼 상태

- 소셜 로그인 진입 전 선택, 새 플랜 만들기의 이름·여행지·날짜·인원, 포스트 작성, 리뷰 작성, 댓글 작성, 마켓 등록 입력값은 폼 상태로 둔다.
- 제출 전 입력값과 검증 오류는 서버 상태나 클라 전역 상태에 올리지 않는다.

## 판단 순서

1. 서버에서 온 값이거나 서버로 저장될 값이면 서버 상태로 분류한다.
2. URL, Deep Link, 공유 링크, 뒤로가기로 복원되어야 하면 URL 상태로 분류한다.
3. 제출 전 입력값이면 폼 상태로 분류한다.
4. 위에 해당하지 않고 앱 내부에서만 유지되면 클라 상태로 분류한다.
